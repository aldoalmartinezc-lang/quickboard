## Reglas para trabajos futuros
- No usar `v0.1.0` como base de entrega; usar `v0.1.1`.
- Mantener la trazabilidad entre HEAD, tag y release pública.
- Si se toca el flujo de entrega, verificar primero `git status`, `git log`, `git tag` y `gh release view`.
- No asumir que una release pública refleja el HEAD local sin verificarlo.
